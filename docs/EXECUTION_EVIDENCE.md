# 带证据的执行约束与计划（v0.34.0）

当前策略仍由实例批准值决定。本模块只核查执行能力，不把未核实资金归零或改投，不承诺成交，不默认 T+1。

## 数据链

1. `POST /v1/execution-evidence`：复用研究证据与变更历史，归档原文引用、HTTPS 公开来源（账户截图可用 attachment:sha256 指纹引用）、获取时刻、发布日期（未知明确 null）、数据日期、引用 SHA256 和可选原文 SHA256。相同来源/内容再次采集幂等复用；新内容保留新版本。归档无需投资配置确认，不自动下载、不自动认定账户适用。
2. `GET /v1/execution-evidence?instrument_code=...`：下一次查询直接读取归档；研究诊断与计划也引用来源。不得把来源条数当作质量评分。
3. `POST /v1/execution-constraint-drafts`：完整替换指定基金/账户/渠道的约束包草稿；需要确切份额类别、账户适用证据和说明。空上限表示有证据证明无限额，不代表未知。不得用 null 补齐没查到的限额。
4. 展示差异与影响，用户明确“确认”后调用草稿 commit；15 分钟过期、基线漂移、错误 token 均拒绝；并发提交和响应丢失后的核对均可幂等。Token 不写日志/Git。来源为转载/未核实或标记未解决冲突时不能批准。确认账户约束不改变策略或成交事实。
5. `GET /v1/weekly-plan-preview` 仍复用原批准策略金额，再读取已批准约束及账户全部已登记申购，计算可执行/未核实/本周期不可执行金额与分笔时窗。不创建任何计划、交易或配置。

## 日历与额度

- 精确起止为带时区时间戳，结尾不包含；参数 `period_start` 与 `period_end` 必须成对，最多 31 天。
- 未指定时沿用既有计划“计划日期起七天”的周期；显示准确边界，不假设自然周。估值日期与执行周期可分开明确传入。
- 每日明确记录交易所、基金开放、渠道受理、QDII 特别开放状态及各层证据、开窗/截止时刻和确认规则。缺日历、未知层、重叠冲突不推断为开放。交易所休市不能被工作日算法抹掉。
- 限额含单笔、单日、累计窗口与生效/失效边界；周期内变更按边界分段。既有已提交、已确认和在途均按申购毛额占用；撤销/退款是否释放由明确批准规则决定，不默认释放。
- 额度范围可为当前渠道账户，或当前基金账户的所有渠道。不能合并未证明同属一个基金账户的不同账户。
- 已登记申购渠道必须匹配批准的渠道名称；空渠道使相关额度未知。当日需要带观察时刻、当日失效时刻、范围及来源的账户剩余额度快照；缺失/过期/同刻冲突均保留未核实。快照已包括观察前申购，只再扣除观察后的新申购和本次安排，避免双扣或漏扣。未来日期安排明确以执行前重查账户剩余额度为条件；不能用 Core 已登记记录宣称覆盖外部未知购买。
- 分笔不低于批准的单笔最低额；每项候选额始终等于可执行 + 未核实 + 不可执行。未核实部分可能可执行也可能不能执行，不偷换成 0 元候选。
- 输出是当时资料下的安排，实际提交前必须重新核查。正式计划仍用现有草稿/冻结；冻结不代替每次执行校验，也不会自动用新约束重写历史计划。

## Codex 操作

`investor-assistant plan --budget 200` 读取默认上下文并只读展示。需要复核特定周期时增加 `--period-start`、`--period-end`（ISO 时区时间）和 `--channel`。不结转历史预算。

命名流程 `evidence-archive`、`constraint-draft`、`constraint-commit` 复用客户端持久写请求日志；响应丢失先查询原证据/草稿/生效约束，禁止盲目重发。参数由 Codex 从 schema 获取，不能让用户复制 ID 或 token。

账户截图引用须保存原件指纹并明确绑定账户，不能跨账户用于约束确认。账户页面应仅保留基金代码/份额、渠道、限额口径、剩余额度、申购状态、受理及确认规则、查看时刻；隐藏姓名、账号、余额之外的无关财务资料、身份信息、验证码及登录令牌。

## 升级与恢复

使用随本版发布的 `runtime/windows/update-value-dca.ps1`，可从任意工作目录调用。所有路径锚定 InstallDir；配置数据库路径不符合现有受支持安装布局时，在停服务前明确失败，禁止猜测或新建空库。

停服务前检查解释器、CLI、配置、数据库存在性和备份目标可写，完成代码/配置/任务定义备份。停服务后创建一致性数据库备份并校验完整性、文件指纹，只有 `recovery.json` 验证通过才允许安装或恢复。残缺目录永远不是恢复集。

备份失败且安装未开始：保持原代码/数据，恢复原先运行的 Core 并检查 health/ready；原来停止则保留停止。安装失败：验证恢复集后恢复代码、数据库和配置，恢复任务定义并诊断；日志区别数据恢复与服务健康，不能仅以 Start-ScheduledTask 成功宣称恢复。

部署前另存配置和调度 XML；部署后确认代码与 Tag、健康、迁移、原业务查询一致，再归档已授权公开资料。本版不切换调度、不补跑历史任务、不激活 v1.7、不提交任何周报。
v0.35.0 起动态额度单独保存；渠道限额和截止规则保留各自来源及有效期。逐基金独立形成约束草稿，账户截图不能反推生效日；详见 RESEARCH_NOTEBOOK.md。
