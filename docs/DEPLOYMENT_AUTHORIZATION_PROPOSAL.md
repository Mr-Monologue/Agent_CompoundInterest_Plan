# 部署授权规则修订提案（待确认，未生效）

本文件只供 Ryan 审阅。本次 v0.37.0 仍使用本次明确授权；AGENTS.md 的现行生产边界保持有效，不因保存、提交或发布本文而扩大权限。

## 建议替换的生产授权条款

Ryan 明确授权某一具体交付阶段包含生产部署后，授权持续覆盖该阶段内、沿现有架构与已批准业务规则完成的常规修复和功能版本，不再按每个软件版本重复确认。授权在该阶段完成、Ryan 撤回、或任务范围发生实质扩大时终止；不自动延续到未指定的下一阶段。新会话可以继承有明确原始授权记录和未完成范围的阶段，聊天摘要或本文自身不构成授权。

在上述阶段内，允许：

- 开发、双平台测试、长期分支合并、Tag 与 Release。
- 对同一本机安装目录进行可读备份、必要短暂停服、安装、启动及现场验收；保留既有服务、账户权限、调度来源、时间与参数。
- 无迁移的更新，以及已测试的非破坏性新增表、索引或可空字段迁移；不得修改、删除或重算既有策略及财务事实。
- 保存明确标记的研究证据、未批准候选和隔离结果；不因软件部署批准研究映射或投资规则。
- 失败时优先回退代码。只有能证明部署后没有新增业务事实、且恢复不覆盖新事实时，才可恢复本次已验证快照；无法证明则停止写入并请求具体恢复确认。

## 每次仍必须满足的交付条件

1. 未提交修改得到保留；Ubuntu 与 Windows CI 通过，发布树及安装文件可核对。
2. 停服前检查生产路径、数据库存在性、备份完整性与恢复条件。部分备份不能标记可恢复。
3. 说明本版范围、迁移和预期影响；版本变化本身不再形成新的确认关卡。
4. 升级后通过真实 HTTP 核对健康、就绪、原业务事实、调度与本轮功能；测试和真实运行证据分开。
5. 在唯一实施清单记录原始阶段授权、适用范围、版本、备份和验收结果。凭据不进入日志或交接记录。

## 必须单独确认的例外

- 策略、基准映射、风险阈值、基金角色或资格、模型晋级、计划冻结、正式报告、资金与交易事实：继续执行原投资治理流程，阶段部署授权不替代具体确认。
- 删除/重建账本、破坏性或不可逆迁移、历史数据修复、可能覆盖新业务事实的数据库恢复。
- 更换技术栈、云迁移、新的对外网络暴露、增加权限、更换任务账户、开机未登录服务、安全或组织限制调整。
- 启用新通知渠道、改变通知接收者、真实试发消息、安装或注册新服务，除非该具体动作已在阶段范围中明确授权。
- 超出当前阶段的新功能目标、重大不兼容变化，或无法满足备份/CI/业务不变性条件。
- 平台审批或凭据限制仍然有效；不得通过换命令、换工具或间接执行绕过拒绝。

## 生效方式

待 Ryan 明确确认上述适用范围及例外后，再将条款写入 AGENTS.md，并在唯一实施清单记录生效时间与范围。只有“确认修订”才批准规则修改；确认软件升级、保存本文、查看提案或批准投资配置都不等于批准本提案。

此次需要决定的是是否采用“按明确阶段持续授权，例外单独确认”的规则；不涉及批准本轮其余研究映射。
