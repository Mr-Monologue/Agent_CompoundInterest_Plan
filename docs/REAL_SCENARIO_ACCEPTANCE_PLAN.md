# 真实场景验收方案（仅准备，未获执行窗口确认）

下列时间均为上海时区的候选窗口，不是已约定任务，不创建自动化、不休眠、不重启、不发送消息。每项独立确认；确认一个不授权另外两个。窗口不合适时由用户另定。

| 项目 | 候选窗口 | 为什么选择 | 通过标准 |
|---|---|---|---|
| 1. 休眠与唤醒 | 2026-09-25 20:50—21:45；拟20:55休眠、21:05唤醒 | 覆盖原21:00行情任务，并观察21:30风险任务；不改时间或参数 | 记录休眠前心跳、到期时刻、唤醒/实际执行时刻；按原补跑规则同次仅执行一次，来源WINDOWS，真实异常和数据质量保留 |
| 2. 重启与登录恢复 | 2026-09-26 07:50—08:20；拟07:55重启、08:05登录 | 验证现有Core登录启动边界和08:00健康任务到期恢复 | S4U后台启动、Core登录后可用、离线记录未丢失，登录后按原策略恢复且无重复；未登录时不可用如实记录，不借测试注册未登录服务 |
| 3. 单条通知收件 | 2026-09-25 20:35—20:45，独立于休眠项 | 用户在线可直接确认收件 | 只读核对现有目标渠道与本人收件账户后，展示目的地和文本，再取得该次试发确认；同一请求最多一次发送，保留出站、提供商回执和本人收件证据 |

通知候选文本：“投资助手验收测试：这是一条不含账户和投资金额的测试通知。无需进行投资操作。”具体发送时间由系统真实记录，不预填伪造时间。目的地尚未确认，不自动选新渠道。当前历史发送失败不清除，平台受理不当作本人收到。响应丢失先查同一请求的回执，不以新请求盲目重发。

每个窗口的前置检查：用户保存正在编辑的工作；Core就绪与当前版本已核验；读取原政策时区/参数/补跑上限；备份验证可读；没有正在确认的交易操作。确认当天重新核对外部待办；系统健康不足时延期，不靠清空失败记录通过验收。

执行记录必须包含：原应执行时间、真实停止/睡眠/启动/登录时间、任务来源、幂等标识、实际执行次数、结果与数据日期、异常和后续动作。历史三次漏跑保持保护，不因测试补跑。用户不在线、目标渠道不明确、任务仍在执行或前置检查失败时不开始。运行结果不符合预期时停止剩余演练，先恢复当前已批准服务状态。

此方案不证明整夜长期稳定性。后续可约定连续7个自然日的被动记录审计：每个到期实例有记录或明确漏跑原因，无重复，心跳缺口可解释；观察不得将历史错误改写成成功。不开新服务、不提高权限、不自动获取持仓和交易。
