# Value DCA Agent 项目背景与接手要求

这是 Ryan 的个人纪律型投资助手。它连接研究、计划、外部购买记录、持仓、执行跟踪与复盘，帮助理解为什么持有、当前变化、新增资金分配依据、需要复核的投资理由和本人待办。长期决策质量和实际可用性是目标；工具数、测试数或短期盈亏不能代替有效性。加快交付不等于提高风险、追涨或批准未经验证的模型。

## 运行与恢复
- Windows 本机 Codex 是开发、日常交互、研究和运维统一入口；用户不充当 Codex 与 Hermes 的传话者。
- Core 是唯一业务规则与账本来源；Windows 后台持续调度；保留 Hermes 其他能力。使用已可用 HTTP，不等待 MCP，不直接读取生产数据库代替业务接口。
- 先读本文、AGENTS.md、PROJECT_STATUS.md、ROADMAP.md、release-manifest.json，再读唯一实施清单 [LAUNCH_CHECKLIST.md](LAUNCH_CHECKLIST.md)；已完成项不重建、不重复安装和迁移。
- 用户实例约定放在被 Git 排除的 `.codex/instance-background.md`，生产快照在私有验收目录并标时间；公开代码不硬编码个人预算、基金池、权重和历史限额。当前持仓、行情、计划、有效策略必须通过 Core 读取。
- 常规预算和不结转等稳定约定不反复询问；具体金融提交仍按当前待确认内容获得明确确认。

## 业务边界
- 用户可跳过或延后；历史未投入不自动结转或形成欠款。优先以新增资金修复配置，不自动卖出。
- 计划、已在外部提交申购、平台确认及正式记账分开；一个计划项可关联分日、多笔真实申购。
- 计划冻结、财务事实记账、正式报告各自确认。不代替用户在支付宝等平台买卖。
- 历史误码、跳过原因、漏跑和估值 WARNING 保留；不用伪造成功或收益清空待办。
- 平台限额必须区分份额类别、账户、渠道、来源、生效期和质量，历史限额不成为永久常量。

## 确认边界
普通实现、测试、源码发布和当前已授权部署连续推进。预算规则、WARNING 金额门槛、备用资金顺序、策略或模型模式变化集中列出真实差异，展示现值、拟议值、影响和不发生事项后再请用户确认；不因阅读附件自动提交。
