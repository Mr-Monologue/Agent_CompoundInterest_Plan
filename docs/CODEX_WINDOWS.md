# Windows 本机 Codex 接入

目标：在同一个本机 Codex 入口完成日常查询、计划与报告操作、源码排查和授权后的部署。
Codex 直接连接现有 `investor_core` MCP，不经 Hermes 转述；Core 和原有数据库继续作为事实来源。
本功能并入尚未发布的 v0.31.8，不能对 v0.31.7 安装目录直接运行接入检查。

## 已实现与边界

- 标准 STDIO MCP，可由 Windows 本机 Codex 客户端、CLI 或 IDE 扩展使用。
- MCP 初始化即提供操作规则，不要求先安装 Hermes Skill。
- `INVESTOR_MCP_ACTOR_REF=codex` 标记新操作的审计来源；默认仍为 `hermes`，不改历史记录。
- 握手预检：检查关键工具、MCP 与 Core 同版本、Codex 操作身份及 `/ready`。
- 预检只调用 `system_health_get(full)`，不加载个人持仓，不创建或提交业务记录。
- 一次注册到本机 Codex 的 `investor_core` 名称，使用已安装的绝对可执行路径。
- `-SkipHermes` 贯穿安装、更新、更新任务重建和回滚；不会要求安装 Hermes 或重启其网关。
- 连接脚本不会退出、卸载 Hermes，也不会关闭旧 Cron。后台投资任务及通知仍需单独迁移、验收。

## 首次接入顺序

1. 核验已发布版本和本机实际安装目录。开发检出与运行目录分开，默认运行目录为
   `C:\investor\value-dca-agent`。先确认已有服务/数据位置，禁止新建空数据库替代旧账本。
2. 完成本版本的测试和发布；生产升级遵循 AGENTS.md 中当前明确阶段授权及例外边界。按现有备份、迁移、回滚流程
   升级，引导脚本或安装器传入 `-SkipHermes`。这会让后续自动更新保持无 Hermes 模式。
   仅接入已升级的运行环境时，跳过此步，不重新安装。
3. 确保托管 Core 已就绪，Windows 当前用户能运行 `codex` CLI。
   连接脚本使用官方 `codex mcp add` 写配置，避免自行重写用户 TOML。
4. 在已升级的运行目录执行：

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\connect-codex-windows.ps1
   ```

   非默认目录需传入 `-InstallDir "D:\实际运行目录"`。
   如只想验证连接，追加 `-CheckOnly`，不会改 Codex 配置。
5. 重启本机 Codex 会话，在 `/mcp` 检查 `investor_core`。不要求更换当前模型或更改其他 MCP。

若 Core 尚未启动，先只读检查 `ValueDCAInvestorCore` 任务与日志；确认任务属于现有安装后
可启动服务，再重试接入。连接器明确关闭 MCP 自动启动/自动修复，避免查询触发依赖重装。
后台 Core 仍由现有 Windows 计划任务在登录时启动并托管，不依赖 Codex 聊天窗口。

脚本将原有用户 `config.toml` 复制为同目录唯一命名备份，尊重已有 `CODEX_HOME`。
随后由 Codex CLI 更新名为 `investor_core` 的配置；已有该名称的定制参数应事先核对。
备份可能含用户私有配置，只保留在本机，不上传 Git。注册失败时保留备份供核对，不自动
覆盖可能被其他客户端同时修改的整个配置。后续版本升级通常无需再次注册同一绝对路径。

官方接口依据：[Codex MCP 配置](https://developers.openai.com/codex/mcp/)。

## 接通后的第一条请求

> 只读检查投资助手的版本、就绪状态、默认组合、当前持仓比例和待办。
> 区分当前实时比例和历史计划快照。不要创建计划、更新行情、修改策略或登记交易。

确认读取的是原有组合后，可按需提出：

- “按当前实际日期预览本周 200 元计划，暂不创建草稿。”
- “预览指定周期整周不投入的记录，不结转预算。”
- “检查这份真实终态计划是否已有正式周报；先展示预览。”

涉及草稿提交、计划冻结、申购/成交记账时，在同一 Codex 会话展示具体内容并等待明确确认。
一项内容已经明确确认后，不为同一动作重复索要确认；更改金额、基金、周期或业务事实后
需要重新确认。开发或升级授权不能用于提交投资事实。

## 同一个 Codex 内开发与运行

- 日常业务统一走 MCP，严禁靠直接 SQL 或修改数据库文件绕过确认。
- 代码调试使用开发检出、临时数据库和测试接口，不在正式安装目录运行可能初始化数据库的测试。
- 出错时可直接读取脱敏日志和源码，保留原草稿身份与幂等键；不要重复创建记录“试一遍”。
- MCP 健康结果同时返回 Core 版本、adapter 版本和审计来源，版本不一致先解决部署问题。
- 保持已批准策略、账本、持仓与用户确认流程；不重新导入历史持仓、不切换一套新数据库。

## 尚未迁移的后台能力

接入 Codex 只替换交互入口，不会把 Hermes Cron 自动搬进 Codex。已启用的旧任务不能直接
删除；需要先列出现有任务和实际触发情况，再迁移到独立 Windows 调度器，验证单次触发、
漏跑补偿、失败恢复和通知接收后停用旧任务。无现成调度时也不能宣称已自动运行。
当前可以在 Codex 手动完成查询、预览和复盘，后台调度迁移是后续独立交付范围。


## 失败恢复保护

代码兼容与数据库快照恢复权限分开。仅业务源码、锁定依赖、数据库结构和迁移版本一致，且旧代码在当前库副本诊断通过时可自动回退代码；当前库及新增事实保留。未知差异明确阻断，不因迁移为新增操作就放行。

具体阻断原因、备份、前滚修复与数据库恢复确认步骤见 [RECOVERY_RUNBOOK.md](RECOVERY_RUNBOOK.md)。代码兼容通过不授予数据库快照恢复权限；不得自动覆盖旧库或删除 WAL。真实灾难恢复尚未演练。
