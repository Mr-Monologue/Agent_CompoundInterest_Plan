# 基线差异复核（v0.40.1）

基线是历史事实，当前是已归档研究的当前观察，差异是有版本的推导。查询不会抓取行情、改写基线、生成新观察点或处理问题。现有 0042 表不变，无迁移。

## 日常操作

|用户意图|只读命令|
|---|---|
|复核我的持仓 / 和基线相比有什么变化 / 查看本次变化|`investor-assistant holdings-review`|
|查看已解决问题|`holdings-review --status RESOLVED`|
|查看新增问题|`holdings-review --status NEW`|
|查看退化项|`holdings-review --status REGRESSED`|
|查看无变化持仓|`holdings-review --status UNCHANGED`|
|查看 000032 的变化与证据|`holdings-review --code 000032 --details`|
|查看所有窗口、完整当前研究|`holdings-research-current --details`|
|查看观察与处理历史|`review-history`|

默认比较首次保存的快照，永远不把上次 GET 或最后一次处理当基线。默认只展开 MATERIAL，MINOR 在详情，NONE 不展开；查询日与归档窗口日期分别显示。Core明确返回本次未获取新证据（仅读取归档），默认摘要同样说明；归档无变化不能解读为最新市场或产品情况无变化。采集状态是查询说明，不参与研究身份或差异计算。没有基线时明确阻断比较并指向首次预览，不能伪报零变化。

## 比较合同

`BaselineService` 选不可变首条快照；`CurrentResearchService` 读取既有 Core 研究，`review_delta.project` 适配原始输入而不更新旧记录；`DeltaEngine` 按身份、结构化值、重要性逐层判断；`delta_presentation` 只展示；`SnapshotService` 负责明确保存。所有接口限定当前组合/账户。

规范化研究对象是“基金＋主题＋窗口”，类别是状态而不是身份，允许 DATA_GAP → OBSERVATION 等迁移。旧分类仍按原值保存，适配成 EVIDENCE_DIFFERENCE、CONFIG_PENDING、OBSERVATION。比较对象数不等于历史分类记录数：同时覆盖所有正负窗口、映射、论点、证据有效期与质量；不新增旧待办。

- 文案、排序、重复引用和重新采集不构成事实变化。引用归档ID不作为内容身份，保存原引用以追溯。内容指纹、来源归属、口径、批准、数值与分类用于判断。
- 同一固定窗口使用准确起止日；明确声明 `window_key` 的滚动窗口可连续比较，只有日期更新且结论不变为 MINOR。未声明窗口族时不猜测“同一个滚动窗口”。
- 数值保留全精度；低于两位展示精度且结论/证据等不变为 MINOR，不是投资阈值。领先落后结论改变仍为 MATERIAL。
- 分类改变在同一差异记录中保存 CLASSIFICATION_CHANGED 的前后类别，不拆成新增加解决。RESOLVED 需要当前结构化解决依据和引用；配置还须当前已由原流程批准。记录消失仅说明不能继续观察，保守显示 REGRESSED，不推断已解决。
- 来源失效、有效期到期、可计算性变差或观察变冲突分别保留退化。只使用既有确认的有效期和依据，不自创“几天过期”的规则；缺少规则保持未知。已在双方过期者为 STALE/NONE，不制造重复重要变化。
- 背景披露非问题、非风险告警。系统/数据/研究 WARNING 分开；源读取失败返回实际错误，不伪造正常研究结果或零变化。原单源与口径限制仍显示。

研究框架不调用任何策略、交易、映射批准、论点批准或处理接口。披露差异仅因条目不再出现不能被自动结案；没有充分核对证据继续显示未知/不可观察。

## 明确保存观察点

只有用户明确说“保存这次复核 / 保存为新的观察点 / 记录本次观察”，才按当前具体预览调用 `workflow review-save`。Codex自行保管首次基线标识、当前状态指纹及固定幂等键，正文 `explicit_save=true`。不要求用户抄参数。若输入变化，重新展示；查询意图不得推断为保存意图。

POST `/v1/holding-review-observations` 在事务中复核当前状态；同一当前状态复用原快照，不加快照、待办或事件。不同状态追加原始快照及一个保存事件，包含 from/to、comparison_version 和 delta_summary，不复制生成的差异文本，不标记问题解决，不创建处理事件。本阶段生产没有保存授权。

GET `/v1/holding-review-observations/{snapshot_id}/delta` 从保存的两端输入按指定比较版本重算，不访问今天的研究批准状态。不支持的比较版本明确阻断，后续修改算法须保留旧版重算能力。原首次保存端点保留兼容，新的纵向保存应使用此新工作流。

响应丢失先读 `review-history` 核对保存事件/指纹，客户端禁止盲目重发；服务端同幂等请求返回原事件，不重复建立记录。保存研究与处理问题是独立动作，处理仍走原流程。

## 验证边界

fixture 验证纵向变化和保存，真实基线只读验证“无变化”同样是成功。生产真实数据仅在私有目录留证，不提交仓库。安装后入口验收与隔离 HTTP 实测分别记录于唯一 LAUNCH_CHECKLIST；未部署前不声称安装可用。
