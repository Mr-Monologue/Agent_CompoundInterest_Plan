# 研究更新与变化复核

v0.44.0，主动触发；复用D2研究输入、计算与版本，D1首次基线和历史分类只读。无新调度、服务或通知。

## 三个入口

- “检查哪些研究需要更新”：`investor-assistant research-update-check`，GET `/v1/research-update-check`。只读归档日期、研究截止、逐来源日期及既有有效期；没有规则为UNDEFINED，不能套用账务行情7天规则或推算新公告已发布。
- “更新研究，告诉我有什么变化”：`investor-assistant research-update`。POST `/v1/research-updates`，本阶段明确授权公开采集、暂存核验及追加独立研究。可用 `--scope 022463` 或 `--scope 003096` 限定单案例。
- “查看上次研究更新结果”：`investor-assistant research-update-last`，GET `/v1/research-updates/latest`，不联网、不重算、不保存。

技术标识由客户端保管，用户不用复制。响应丢失先回读原请求；不存在或中断时，代理核对状态后使用 `--resume` 沿原标识恢复，不能换键重发。Core对运行中的不同请求合并回读；新检查最少间隔30秒。没有每日自动更新。

## 范围与核验

仅022463/022424指数联接A、003096/009163医疗主动C。现有其他候选/持仓不扩大、不称全部刷新。每次依序取得准确份额官方单位净值、分红、CSI实际日期网格，以及天天基金净值/分红；实际请求产品披露页，并尝试央行一般现金依据。页面访问成功不证明公告目录完整；新文件未经内容核验不会替换产品规则/结构结论。一般利率不自动适配基金95/5现金腿。

固定公开主机白名单、HTTPS证书校验、不跟随重定向、不登录或绕过限制。每请求15秒、只对传输错误最多重试1次、同主机至少0.6秒、每案例480秒总预算、12MB响应上限。401/403/429等HTTP错误不盲目重试。单来源失败继续独立检查；官方净值/分红/日历输入组不全、份额不符、未来日期、缺日、跨渠道冲突均阻断该案例发布。已有渠道验证的医疗案例还要求本次渠道输入组完整一致，不能沿用旧核验序列发布新窗口。

原文先进入内容寻址暂存，保留来源、获取/完成时间、数据区间、原始指纹、语义指纹及可回读原文；发布时间无法证明时为未知。解析失败原文仍保留。JSON字段顺序、净值末尾零、抓取时间、页面装饰不生成新研究事实。检查事件与证据/研究版本分离；同内容不新增版本。原始日序列不插值、不拼接份额，不将累计净值当复权，不重复扣净值中的费用。

跨渠道只作发布渠道核对；上游独立性未知不清除WARNING。逐日精确值有差异即保留待核，不临时拟合容差放行；报告仍用原计算显示精度区分可见差异与微小变化。分红单位按已核实每10份转每份；未支持非空格式不能视为零分红。已知2021历史分红接口遗漏仍在旧版本及限制内，不修历史。

## 版本与恢复

已有四个固定窗口保持起止，两个既有滚动窗口只将终点推进至完整共同日期；不随查询年份暗改窗口规则。范围/结构/费率沿旧正式文件生效期，结构披露日期不冒充此次净值截止。每个新版本用本次完整主输入组，旧版本可继续按版本回读。

新增两张研究运行/公开暂存表。运行唯一约束与持有者校验防止并发发布；30分钟接管租期大于两案例请求预算。中断后显式恢复，同一已暂存输入不重采；一个案例的研究版本归档与运行完成记录在同一SQLite事务提交，提交前崩溃整体回滚，提交后重放复用记录。已成功案例不因另一案例失败丢失。最新失败状态与最后成功研究分开，不刷新旧研究日期。

部署遵循当前阶段授权、双平台门禁和可读备份。新增表不是旧代码兼容证明：回退须用当前数据库副本验证旧版本就绪与业务入口；未通过必须停止回退并保留当前数据库，优先原版本修复。数据库快照恢复是独立权限，不能覆盖升级后研究或业务新增事实，不能凭新增迁移自动恢复旧快照。

## 展示与边界

默认总结检查范围、成功/受阻、取得证据和截止、固定窗口修订/滚动推进/可见数值与单位、下一步。滚动收益变化不解释成基金能力变化，没有投资实质阈值不虚构阈值。指数下一步由现金腿、目标ETF/现金配置、渠道核验缺口生成，不复用主动选股提示。

组合研究事项按同一下一步合并，默认最多3项；先补阻塞比较的证据，再核实影响已知结论的事项，配置确认及维护分列。不是基金优劣或交易排名，背景事实不作风险告警。

不更新账务估值来源、不批准映射/论点、不改资金规则、不关闭D1旧问题。现场证据与阶段状态以LAUNCH_CHECKLIST末尾为准。
